# Storing Data
For this project I had to figure out a data structure for storing the expense description and amount. Hmmm... we have 2 connected pieces of data, right? Kind of like a Key, Value relationship wouldn't you say? 💡 Let's use a dictionary! Have the description be the key and the amount as the value. How could this go wrong? Well at first it was fine. But then dictionaries in Python have a really handy feature that totally undermines my simple genius. Python dictionaries do not allow duplicates! (Yes, I am *that* rusty). So my initial data structure worked fine as long as the user didn't try and track multiple of the same expense...
```python
# simple, yet naïve 
expenses = {"Lunch": 15.50, "Dinner": 99.99, "Taxi": 50}
```

After running into this issue of duplicate entries in a dictionary I realized that I need to revise my data storage structure. So the better way to structure the data is as a list of dictionaries, with descriptive keys in the dictionaries so we know what is being stored in there. Much like a database table and the fields within it, or a JSON object. This structure not only allows for duplicate expenses, it is also easily scalable. For example, if we want to start tracking the employee's name with the expense then we can just add another key to the dictionary for "employee_name".
```python
# ahh... much better!
expenses = [
    {"description": "Lunch", "amount": 15.50},
    {"description": "Dinner", "amount": 99.99},
    {"description": "Taxi", "amount": 50}
]
```

# User Input. Ewww...
To get the expense data we have to let users type in the description and amount. This never goes well. Users CANNOT be trusted! And the Python `input()` function is wide open to accept anything.

Here's the function for adding an expense. It gets the description and amount from the user.
```python
def add_expense(expenses):
    ''' get description and expense amount from user and add to dict '''
    print()

    # Description can be alphanumeric, we don't care. It DOES need to be
    # within 23 characters though, so truncate it
    desc = input("Expense description: ")[:23]

    amt = input("Expense amount: ")

    # Clean up any punctuation from the input string, e.g. $ , : ' etc...
    amt = remove_special_chars(amt)

    # Check if remaining string is a number
    if is_number(amt):
        expense = {"description": desc, "amount": float(amt)}
        expenses.append(expense)
        print("\nExpense added successfully!")
    else:
        print("\nERROR: Expense amount not a valid number...")
        print("Expected format: 9999.99")
```
There is no validation for the description. I have truncated it to 23 characters because that is what fits in the columns for the printing of the expenses, so anything *over* 23 characters would be lost to the user anyways. But, there should be two things added to the description validation to make it more user friendly:
1. We should not allow a blank description.
2. The user should get a warning that the description can only be 23 characters long.

The validation for the amount is more involved. Python's `input()` function deals in strings, but we want a float. The first thing I did was cleanup special characters from the input. ChatGPT kept questioning why I did this and argued that the user input should not be cleaned up this way. However, I have many years of experience being and observing humans to know that they would prefer it this way. A human could type a monetary value in many ways:
- 12.34
- 1,000.99
- $55,000
- £30.98

You *could* frustrate the user by telling them that their formatting is invalid when they type $50.00 instead of 50.00. Or you could take that into consideration and clean up the special characters so that the user doesn't need to concern themselves with $50.00 vs 50.00 vs 5,000$.

```python
def remove_special_chars(input_string):
    ''' remove special characters from a string '''
    special_chars = string.punctuation
    for char in special_chars:
        if char != ".":
            input_string = input_string.replace(char, "")

    return input_string
```

After the special characters have been cleaned up we need to check that what remains is a float. From reading the documentation I found that `isdigit()` and other methods will return `True` for weird edge cases, like blank strings. So instead we can try forcing a type change with the `float()` method. If that fails then we know that the data is not what we want for our amount.

```python
def is_number(num):
    ''' check if a string is a number. built in isdigit and other methods fail
        for decimal numbers and other numbers '''
    try:
        float(num)
        return True
    except ValueError:
        return False
```

# Refining the program menu

Simple, gross, but it works! There has to be a better way though right? Well, that ChatGPT showed me in my code review stage that functions can be stored in dictionaries and called when accessed 🤯

```python
def main():
    ''' startup and main program go in here '''
    # add user options to dictionary inside a list
    options = [
        {"name": "Add expense", "func": add_expense},
        {"name": "View expense", "func": print_all},
        {"name": "View total", "func": print_total},
        {"name": "Exit", "func": exit_program}
    ]

    # Store expenses in list of dictionaries
    expenses = []

    display.program_header("EMPLOYEE EXPENSE TRACKER")

    while True:
        display.options(options)

        user_choice = input("Select an option: ")

        try:
            selected_menu_item = int(user_choice)
            if selected_menu_item <= 0 or selected_menu_item > len(options):
                raise ValueError()

        except ValueError:
            print(f"\nERROR: '{user_choice}' is not a valid option...")

        except IndexError:
            print(f"\nERROR: '{user_choice}' is not a valid option...")

        else:
            options[selected_menu_item - 1]["func"](expenses)
```
Check *that* out! If you include the parenthesis then the function will run and store the return value in the dictionary. Omit the `()` and you store the function itself and can call it. Very clever and much more scalable/maintainable!
